# 自动更新

客户端并行拉取 GitHub 与 Gitee 上的静态清单 `update/manifest.json`，以及更新包下载地址；**哪个先成功用哪个**（另一侧失败不影响）。

## 启动前检查

开启设置项「启动前检查更新」时，在**创建主窗口之前**拉取清单比对版本：

1. 有新版本 → 原生对话框询问是否安装
2. 用户确认且「确认后自动安装」开启 → 下载、校验、应用并退出当前进程（安装脚本拉起新版本）
3. 用户选择暂不更新 → 记录该远程版本，下次启动同版本不再询问（设置里手动「检查更新」仍会询问）
4. 清单拉取失败 → 静默跳过，照常进入主界面

## 应用更新注意

- 便携版优先下载 zip，解压后由旁路脚本拷贝并重启；**应用阶段不得清空暂存目录**（否则解压结果会被删掉）。
- 若当前 exe 位于 Program Files，优先下载 setup.exe，以 NSIS `/S` 静默安装后再拉起新版本。
- 用户在启动询问或主界面点「稍后/否」会记下远程版本，同版本下次启动不再询问。

## 更新包

清单里的 `installer` / `zip` / `linux` 主 URL（通常写 Gitee Release）会自动推导对端 GitHub（或反向）镜像，下载时两端并行，先校验通过者落盘。

## 字段

| 键 | 说明 |
|----|------|
| `latest_version` | 最新版本号（如 `2.3.1`） |
| `min_supported_version` | 最低仍支持版本（预留） |
| `channel` | 通道名，如 `stable` |
| `notes` | 更新日志正文（弹窗展示） |
| `zip` | Windows 便携包 `{ url, sha256 }`（优先） |
| `installer` | Windows 安装包 `{ url, sha256, user_interface? }` |
| `linux` | Linux 包 `{ url, sha256 }` |
| `release_notes_url` / `html_url` | 发行说明页 |

## 发版约定

Gitee Release **只保留最新一版**（附件配额有限；发新版前先删旧 Release / 附件）。GitHub Release 建议同步上传同名附件，以便镜像竞速。

步骤：

1. 打包 Windows 安装包 / 便携包 / Linux 包
2. 删除 Gitee 上旧的 Release（及标签，如需要）；GitHub 可保留历史或按需清理
3. 在 Gitee 与 GitHub 创建新版 Release 并上传上述三个包（文件名一致）
4. 改本仓库 `update/manifest.json` 的版本、`notes` 与 URL（填 sha256；主 URL 写一侧即可）
5. 推送到 GitHub `main`，并同步到 Gitee `master`（或运行 `python tools/publish_gitee_manifest.py`）

本机发版用私人令牌写在仓库根 `.gitee_token`（已 gitignore / 打包排除，勿提交、勿打进发行包）。
